# 植早早

一个记录植物生长、养护、环境与纪念的微信小程序。数据全部保存在本机（无需后端），用微信开发者工具导入即可运行。

## 一、导入与运行

1. 下载本项目文件夹（或解压 `plant-recorder.zip`）。
2. 打开【微信开发者工具】（下载地址：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html ）。
3. 点击 **导入项目**，目录选择本文件夹。
4. AppID 已填 `wx0a6ce3c13d086a96`，导入后直接使用该小程序即可。
5. 导入后点击 **编译** 即可在模拟器中运行。

> 说明：本项目使用 `wx.chooseMedia` / `wx.saveFile` 处理图片，真机调试即可正常拍照上传。账号登录使用云开发环境 `cloud1-d7gtudpmj14f1bb15`，配置在 `config/env.js`。

### 本地质量检查

电脑安装 Node.js 18 或更高版本后，在项目根目录执行：

```bash
npm run check
```

该命令会检查 JavaScript 语法、JSON 配置、WXML 标签结构，并运行日期与提醒算法单元测试。微信专用 API、样式和真机图片权限仍需在微信开发者工具中验证。

## 二、功能总览

| 模块 | 说明 |
| --- | --- |
| 主页 | 植物图片墙（每株以图片卡片显示）、总投入金额统计、今日需浇水 / 逾期待办统计、近期待办列表，并简略显示登录状态 |
| 我的 | 底部最右栏。用户可自行授权微信头像和昵称，云函数按当前微信绑定账号；可更新资料或退出本机登录。未登录时四个栏目都能浏览，保存记录前才会提示登录 |
| 植物信息 | 名称、品种、状态、价格、购买途径、种植形式、所在位置、购买日期、陪伴起始、备注、照片 |
| 生长环境 | 自定义环境分类（如阳台直射、半阴散射光），每个环境单独设置**光照强度（lux 勒克斯）**与**每日光照时长（小时/天）**，附 lux 参考表 |
| 种植形式 | 水苔、土培、水培、板植、颗粒 |
| 养护记录 | 可无限添加：**浇水、施肥、修剪、换盆、防治病虫害、测量**，每条可附文字与照片，形成时间线 |
| 提醒 | 浇水 / 施肥 / 换盆 三种提醒，按季节自动频率，也可为每株植物单独设置间隔天数 |
| 纪念碑 | 植物「送人」或「去世」时建立纪念碑，记录日期、纪念语与陪伴时长，可随时恢复为活跃植物 |

## 三、提醒机制（重点）

### 浇水频率（默认按季节自动）
- **春（3-5月）**：每 **10** 天
- **夏（6-8月）**：每 **5** 天
- **秋（9-11月）**：每 **10** 天
- **冬（12-2月）**：每 **15** 天

### 自定义间隔
- 浇水间隔：留空 = 按季节自动；也可填自定义天数覆盖。
- 施肥间隔：默认 30 天，可自定义。
- 换盆间隔：默认 365 天，可自定义。

### 到期计算方式
从该植物**最近一次对应类型的养护记录日期**（浇水→最近一次浇水、施肥→最近一次施肥、换盆→最近一次换盆）起算下一周期；若无记录则从陪伴起始 / 购买日期起算。主页与提醒页展示未来 14 天内的近期任务，逾期任务始终展示，文案为“还有 N 天 / 今天到期 / 逾期 N 天”。提醒页点击“完成”会进入养护记录页并自动选中对应类型。

> 关于推送：打开小程序时会直接看到到期和逾期任务。微信订阅消息不是持续后台推送，每次授权通常只能发送有限次数。定时云函数 `sendDueReminders` 会在每天 9:00（中国时区）给已授权用户发送当天到期的浇水、施肥、换盆提醒；`config/env.js` 里的模板 ID 为空时，这条链路不会发送，应用内提醒不受影响。

## 四、数据与存储

- 登录后的植物、环境、养护记录和纪念数据以云数据库为准，按微信用户隔离。页面不再把本地缓存当作正式数据源。
- 升级前已经写在本机的 `plants`、`envs`、`memorialPlants` 会在登录后提示迁移。迁移可重复执行，同一次旧编号不会重复创建。本机原数据不会自动删除。
- 账号身份以云函数读取的微信 `OPENID` 为准，不使用客户端自报的用户 ID。头像和昵称由用户在「我的」确认后写入 `users` 集合。
- 植物照片和养护照片上传到云存储，数据库只保存 `fileID`。选择照片时会先在本机持久化，保存档案时再上传；上传失败会提示重试，不会把临时路径写进云端。
- 云数据库集合：
  - `users`：昵称、头像、迁移状态、订阅授权
  - `plants`：植物档案、提醒间隔、纪念状态、软删除
  - `care_records`：养护记录，按植物分开存放
  - `environments`：光照环境
  - `memorials`：纪念碑
  - `notification_logs`：订阅消息去重和发送结果
- 建议在云开发控制台为这些查询建立索引：`plants` 的 `_openid + deleted`，`care_records` 的 `_openid + plantId`，`memorials` 的 `_openid + plantId`，`notification_logs` 的 `dedupeKey`。

## 十、账号登录

打开小程序后可以直接浏览首页、环境、提醒和纪念碑，底部菜单始终可用，不会立刻要求授权。云端植物数据在登录后才读取。用户进入「我的」或在保存记录时，可以自行选择授权头像和昵称；小程序不获取手机号。登录状态保留 7 天，过期后仍可继续浏览，重新授权后再读写云端数据。云端还没有环境时，会在登录后写入四条默认环境。登录分两步：

1. 云函数 `login` 读取当前微信身份，并在 `users` 集合中创建或更新该用户。客户端不能指定别人的用户 ID。
2. 用户点头像授权选择微信头像或相册图片，在昵称框点选微信昵称或自行填写，再点「授权登录」。

退出登录只清除本机保存的头像、昵称和登录状态。云端植物数据仍绑定这台微信，重新登录后从云端恢复显示。升级前的本机数据不会被删除。

首次登录前，请在微信开发者工具或云开发控制台完成：

1. 云函数目录：`login`、`savePlant`、`saveEnvironment`、`deleteEnvironment`、`saveRecord`、`deleteRecord`、`memorializePlant`、`restorePlant`、`deletePlant`、`migrateLocalData`、`exportUserData`、`sendDueReminders`。环境 ID 是 `cloud1-d7gtudpmj14f1bb15`。部署时选择「云端安装依赖」。
2. 把 `users`、`plants`、`care_records`、`environments`、`memorials`、`notification_logs` 的权限设为「仅创建者可读写」。云函数写入时会带上当前用户的 `_openid`。
3. 在小程序公众平台填写用户隐私保护指引，声明昵称、头像和选中的照片。未声明时，头像选择和相册会被微信拦截。
4. 云存储需允许登录用户上传 `avatars/`、`plants/` 和 `records/`。
5. 订阅消息要在 `config/env.js` 填入模板 ID，模板字段使用 `thing1`（植物）、`thing2`（事项）、`date3`（日期）。未填写时定时函数不会真正发消息。

当前只有一个云开发环境 `cloud1-d7gtudpmj14f1bb15`，还没有单独的开发环境。登录后的读写只走云端，不会和本机数据双写。
