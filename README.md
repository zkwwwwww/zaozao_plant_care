# 植早早

一个记录植物生长、养护、育苗、花费与纪念的微信小程序。登录后的数据保存在微信云开发，按微信用户隔离；未登录也可以先浏览。

## 一、导入与运行

1. 下载本项目文件夹（或解压 `plant-recorder.zip`）。
2. 打开【微信开发者工具】（下载地址：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html ）。
3. 点击 **导入项目**，目录选择本文件夹。
4. AppID 已填 `wx0a6ce3c13d086a96`，导入后直接使用该小程序即可。
5. 导入后点击 **编译** 即可在模拟器中运行。

> 说明：本项目使用 `wx.chooseMedia` / `wx.saveFile` 处理图片，真机调试即可正常拍照上传。账号登录使用云开发环境 `cloud1-d7gtudpmj14f1bb15`，配置在 `config/env.js`。

### 本地质量检查

电脑安装 Node.js 18 或更高版本后，在项目根目录执行：

```bash
npm run check
```

该命令会检查 JavaScript 语法、JSON 配置、WXML 标签结构，并运行日期与提醒算法单元测试。微信专用 API、样式和真机图片权限仍需在微信开发者工具中验证。

## 二、功能总览

| 模块 | 说明 |
| --- | --- |
| 主页 | 植物图片墙（每行 2/3/4/6 个可切换，偏好存本机）、标签筛选和今日待办聚合。主页不显示价格和季节默认浇水说明 |
| 育苗 | 名称、繁殖方式（10 种）、育苗日期必填；母株可选我的植物、我的育苗或手写来源（附照片）；另有照片、计划数量、格位（行 × 列）、基质、容器、育苗场所、备注 |
| 族谱 | 由育苗的母株关系自动生成，从最早的祖先展开所有子代，多代可点击跳转。手写来源不进族谱 |
| 花费 | 日期、类别（农资花费 / 肥料 / 药剂 / 补光灯 / 其他）、金额。支持日/周/月/年统计，并汇总在养植物总价、最贵植物和单价列表 |
| 标签 | 新建、重命名、删除；植物可多选标签，不选即为「未分类」；可把某个环境一键归并为同名标签 |
| 我的 | 底部最右栏。用户可自行授权微信头像和昵称，云函数按当前微信绑定账号；可更新资料或退出本机登录。未登录时四个栏目都能浏览，保存记录前才会提示登录 |
| 植物信息 | 名称、品种、状态（健康 / 病害 / 虫害 / 待观察 / 休眠 / 死亡；旧值读取时自动归并）、标签、价格、购买途径、种植形式、所在位置、购买日期、陪伴起始、备注、照片 |
| 生长环境 | 自定义环境分类（如阳台直射、半阴散射光），每个环境单独设置**光照强度（lux 勒克斯）**与**每日光照时长（小时/天）**，附 lux 参考表 |
| 种植形式 | 水苔、土培、水培、板植、颗粒 |
| 养护记录 | 可无限添加：**浇水、施肥、修剪、换盆、防治病虫害、测量**，每条可附文字与照片，形成时间线 |
| 养护 | 统一提供单株养护、按标签/环境筛选后多选批量养护、养护提醒，以及可筛选、编辑的养护记录 |
| 纪念碑 | 植物「送人」或「去世」时建立纪念碑，记录日期、纪念语与陪伴时长，可随时恢复为活跃植物 |

## 三、提醒机制（重点）

### 浇水频率（默认按季节自动）
- **春（3-5月）**：每 **10** 天
- **夏（6-8月）**：每 **5** 天
- **秋（9-11月）**：每 **10** 天
- **冬（12-2月）**：每 **15** 天

### 自定义间隔
- 浇水间隔：留空 = 按季节自动；也可填自定义天数覆盖。
- 施肥间隔：默认 30 天，可自定义。
- 换盆间隔：默认 365 天，可自定义。

### 到期计算方式
从该植物**最近一次对应类型的养护记录日期**（浇水→最近一次浇水、施肥→最近一次施肥、换盆→最近一次换盆）起算下一周期；若无记录则从陪伴起始 / 购买日期起算。每株植物默认提前 1 天显示提醒，可设置为 0–30 天；逾期任务始终展示，文案为“还有 N 天 / 今天到期 / 逾期 N 天”。养护页的提醒区域支持全部、按逾期时间、按植物和按类型切换，点击“完成”会进入养护记录页并自动选中对应类型。

> 关于推送：打开小程序时会直接看到进入提前提醒范围和已经逾期的任务。微信订阅消息不是持续后台推送，每次授权通常只能发送有限次数。定时云函数 `sendDueReminders` 会在每天 9:00（中国时区）按照每株植物设置的提前天数发送浇水、施肥、换盆提醒；`config/env.js` 里的模板 ID 为空时，这条链路不会发送，应用内提醒不受影响。

## 四、数据与存储

- 登录后的植物、环境、养护记录和纪念数据以云数据库为准，按微信用户隔离。页面不再把本地缓存当作正式数据源。
- 页面长列表统一按每页 20 条展示，滚动到底部后继续加载下一页；统计、筛选和关联关系仍基于完整数据计算。
- 升级前已经写在本机的 `plants`、`envs`、`memorialPlants` 会在登录后提示迁移。迁移可重复执行，同一次旧编号不会重复创建。本机原数据不会自动删除。
- 账号身份以云函数读取的微信 `OPENID` 为准，不使用客户端自报的用户 ID。头像和昵称由用户在「我的」确认后写入 `users` 集合。
- 植物照片和养护照片上传到云存储，数据库只保存 `fileID`。选择照片时会先在本机持久化，保存档案时再上传；上传失败会提示重试，不会把临时路径写进云端。
- 云数据库集合：
  - `users`：昵称、头像、迁移状态、订阅授权
  - `plants`：植物档案、提醒间隔、纪念状态、软删除
  - `care_records`：养护记录，按植物分开存放
  - `environments`：光照环境
  - `memorials`：纪念碑
  - `seedlings`：育苗，`motherType`（plant / seedling / text）+ `motherId` 记录母株
  - `expenses`：花费流水
  - `tags`：标签；植物上用 `tags` 数组保存标签 ID
  - `notification_logs`：订阅消息去重和发送结果
- 建议在云开发控制台为这些查询建立索引：`plants` 的 `_openid + deleted`，`care_records` 的 `_openid + plantId`，`memorials` 的 `_openid + plantId`，`seedlings` 的 `_openid + motherType + motherId`，`expenses` 的 `_openid + date`，`notification_logs` 的 `dedupeKey`。
- 状态为「死亡」的植物不再生成提醒、不参与批量养护；标记死亡时只询问是否建纪念碑，不会自动建。

## 十、账号登录

打开小程序后可以直接浏览首页、环境、养护和纪念碑，底部菜单始终可用，不会立刻要求授权。云端植物数据在登录后才读取。用户进入「我的」或在保存记录时，可以自行选择授权头像和昵称；小程序不获取手机号。登录状态保留 7 天，过期后仍可继续浏览，重新授权后再读写云端数据。云端还没有环境时，会在登录后写入四条默认环境。登录分两步：

1. 云函数 `login` 读取当前微信身份，并在 `users` 集合中创建或更新该用户。客户端不能指定别人的用户 ID。
2. 用户点头像授权选择微信头像或相册图片，在昵称框点选微信昵称或自行填写，再点「授权登录」。

退出登录只清除本机保存的头像、昵称和登录状态。云端植物数据仍绑定这台微信，重新登录后从云端恢复显示。升级前的本机数据不会被删除。

首次登录前，请在微信开发者工具或云开发控制台完成：

1. 云函数目录：`login`、`savePlant`、`saveEnvironment`、`deleteEnvironment`、`saveRecord`、`deleteRecord`、`memorializePlant`、`restorePlant`、`deletePlant`、`migrateLocalData`、`exportUserData`、`sendDueReminders`、`manageSeedling`、`manageExpense`、`manageTag`、`batchCare`。环境 ID 是 `cloud1-d7gtudpmj14f1bb15`。部署时选择「云端安装依赖」。
2. 把 `users`、`plants`、`care_records`、`environments`、`memorials`、`seedlings`、`expenses`、`tags`、`notification_logs` 的权限设为「仅创建者可读写」。云函数写入时会带上当前用户的 `_openid`。
3. 在小程序公众平台填写用户隐私保护指引，声明昵称、头像和选中的照片。未声明时，头像选择和相册会被微信拦截。
4. 云存储需允许登录用户上传 `avatars/`、`plants/` 和 `records/`。
5. 订阅消息要在 `config/env.js` 填入模板 ID，模板字段使用 `thing1`（植物）、`thing2`（事项）、`date3`（日期）。未填写时定时函数不会真正发消息。

当前只有一个云开发环境 `cloud1-d7gtudpmj14f1bb15`，还没有单独的开发环境。登录后的读写只走云端，不会和本机数据双写。

- “我的 → 导出 Excel 表格”生成 `.xlsx`，包含导出说明、植物档案、养护记录、手动任务、花费、育苗、环境、标签、纪念记录共 9 张表。中文表头可筛选，首行冻结，日期和金额为可排序的实际值。保留同名植物的编号与历史记录，不导出微信身份，不再截断复制 JSON。照片仅保留云端引用，不是离线照片备份；暂不支持表格导入恢复。
- 导出按当前账号读取未删除数据，通过编号游标分页，不再限制前 1,000 条。读取失败会整次报错，不会提供缺页表格。单次数据（含手动任务）最多 50,000 条，超限明确提示。导出期间请避免同时在其他设备修改数据，当前实现不是数据库快照。

### 部署与检查

1. 更新 `batchCare`、`exportUserData` 云函数，选“云端安装依赖”。`exportUserData` 新增 `exceljs@4.4.0`。建议批量与导出函数的超时设为 60 秒，导出内存设为 512 MB，并根据实际数据量调整。
2. 导出由云函数生成并上传到 `exports/`，返回短期下载地址。将该云环境的云存储 HTTPS 域名配置到小程序“downloadFile 合法域名”，不能仅依靠开发者工具里的“不校验合法域名”。保持云文件私有，不要开放所有用户读取。临时地址最多有效 10 分钟，含有访问凭证，勿记录或公开分享。
3. 文件下载后客户端请求云函数清理临时云文件，清理接口只允许操作当前账号对应目录。为 `exports/` 额外设置短期自动过期规则，清理断网或强制退出留下的文件。文件下载到本机后可预览、通过预览菜单保存，或点击“发送到微信”。
4. 使用真机检查转发好友、朋友圈介绍、下载域名校验、空数据导出、同名植物、超过 100 项的批量维护及部分失败重试。自动检查不能代替微信客户端与云端部署验收。

本地安装导出函数依赖后运行 `npm run check` 可执行真实 XLSX 写入/重读测试；没有安装时该项会明确跳过。依赖安全检查仍有告警，主要来自项目沿用的 `wx-server-sdk@2.6.x`，也包含 ExcelJS 的压缩依赖。生产端仅从受限的自有数据生成表格，不接收上传的 Excel 或用户提供的文件路径/压缩匹配规则。本次未强制升级整个云开发 SDK，后续需单独验证所有云函数再升级，不能把功能测试通过当成依赖安全检查通过。

## 十三、1.1.2 原生菜单分享

- “我的”、环境、养护等页面以前只有好友分享回调，没有朋友圈回调，因此右上角菜单显示灰色“当前页面未设置分享”。现在所有页面均提供“发送给朋友”和“分享到朋友圈”，不再要求先进入应用介绍页。
- 朋友圈回调不能修改落地页路径，因此统一用 `appShare=1` 查询标记和 `share-preview` 组件展示公开介绍。朋友圈单页模式（场景值 1154）及带该标记的入口都会跳过原页面生命周期；不读取账号、植物、价格或草稿，不创建待办/更新弹窗。普通使用仍保留原页面逻辑，旧微信不支持朋友圈菜单时会回退到好友分享。
- 从朋友圈单页模式进入完整小程序后，会恢复云开发初始化；再次切换不会重复初始化。公开介绍中的进入按钮只在完整模式显示，并重新打开首页，避免首页一直停留在分享预览。
- 这次修复仅涉及小程序前端，不需要重新部署云函数。请更新体验版或正式版，并在手机微信的“我的”与“养护”页检查右上角菜单和朋友圈公开预览；云函数部署或本地测试通过不会更新用户手机上的旧前端。
